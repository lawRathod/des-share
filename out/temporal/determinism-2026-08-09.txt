ROOT CAUSE (proven, not inferred): Go's `select` statement pseudo-randomly
chooses among ready cases using the runtime fastrand, which testing/synctest
does NOT virtualize. Probe: 4 consecutive bubbles in one process each
`select` 1000 times between two closed channels -> a=514/497/496/495
(split differs per bubble). The real Temporal server inside the bubble is
full of multi-ready-channel selects, so task routing, retry counts, virtual
elapsed time, and snapshot series vary per run. The virtual TIMELINE is
deterministic (identical 101 monitor windows with identical StartMs/EndMs in
two retry_amp runs); only per-window VALUES differ. No cross-run state
leakage (values jump non-monotonically: retry_amp attempted 496..524).
Harness/collector/exporter are deterministic; the runtime primitive escapes
the bubble. This is a Go 1.26 runtime limitation, not a GoDES bug.
